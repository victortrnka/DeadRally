# M7: verification against the original

The checks of the M7 spec (section 5), run against the original `dr.exe` under Wine with `scripts/reference-run.sh`, which starts it with `-window -nogl` (and `-smooth` with `--smooth`). Screenshots stay under `captures/`.

## Results

| Check | Scenario | Result |
|---|---|---|
| The software picture smoothed (`-nogl -smooth`) | `startup` with `--smooth`: the intro, the logos and the title, no keys | **Pass.** All 25 shots equal our smoothed picture (`find --smooth`): the intro's 320x200 frames with the means of their neighbours between their pixels, column 639 black and the last row a mean with the black row under it; the 640x480 screens as they are. The frontend with `-window -nogl -smooth` on a virtual display showed the same picture: its window, cut from a screenshot, equals our frame at ticks 780 to 783. |

| The first start without game data | the frontend with `-window` on a virtual display, no `--data`, no `DEADRALLY_DATA`, an empty config folder, D-Bus out of reach (so SDL's dialog falls back to zenity there, not to a portal on the real display) | **Pass, by script.** The message saying no data was found and that a folder dialog comes next, then the folder dialog. Choosing `~/games/DeathRally` wrote `data_path` to the new `config.toml`, and the game went on to its menu. A folder without the game is reported as the config file's, and the next start asks again. |
| The packages | `.github/workflows/release.yml` on a push of 433751a | **Pass.** Each package was built and packed on its system: Linux on Ubuntu 22.04, Windows, and macOS as a universal, ad-hoc signed app (arm64 and x86_64). Each was then unpacked, and its program ran the test scene for ten seconds, counting ticks (`scripts/smoke-test.sh`; Linux under Xvfb, the sound to SDL's dummy driver). The packages are 2.4 MB (Linux), 1.8 MB (Windows) and 4.1 MB (macOS). |

## What the original does that the decompilations do not say

- **Its OpenGL picture filters the 640x480 screens always** (`GL_LINEAR`, 0x43B898), and the 320x200 ones only with `-smooth` or after F12 (0x43B6A2). DeadRally's scaled picture now does the same.
- **Its software picture with `-smooth`** (0x43BA99) is not filtered by the system: see the spec's section 3.

## Review

A fresh review of the branch found nothing Critical. Its four Important findings were fixed, with tests that failed first where code could test them:
- **The folder dialog only where choosing can help:** when no folder is given anywhere, or the config file's is not the game (`the_folder_dialog_is_offered_only_when_choosing_can_help`). A broken config file or a wrong `--data` is reported as it is. A display option that is not true or false is a warning, so it no longer stops the game finding its data (`a_display_option_that_is_not_true_or_false_is_a_warning`). The config file's warnings now show in a message box.
- **No console window on Windows:** the release build is a Windows program, not a console one; the release workflow's smoke test still reads its output.
- **The README's way past Gatekeeper and SmartScreen:** on macOS 15, System Settings' "Open Anyway"; on Windows, "More info", then "Run anyway".
- **Errors a player can see:** the errors from the options and the window or sound setup show in a message box. Finder's `-psn_` argument is ignored (`macos_launch_arguments_are_ignored`).

These minor findings were fixed as well:
- the release workflow's Pack step failing with `package.sh`;
- Quit ending the wait for the dialog;
- the warning when the config file cannot be written;
- the README's Esc, which asks first;
- the README's links, which point at GitHub from inside a package;
- the comments saying why the picture tests matter.

Deferred minors:
- **A wrong folder chosen ends the game:** its message does not say that the next start asks again.
- **`save_data_path` loses the file's comments and order:** its documentation says so, and it only runs when the file did not name a usable folder.
- **`spike-check.sh`'s shot names:** they still say "nearest" and "bilinear" for 640-wide screens, which are always filtered now.
- **Column 639 when F12 turns smoothing on:** in the original it keeps the doubled picture's last column, which DeadRally shows black; it is one pixel wide.
- **The macOS app's version:** a development build's `dev-` version or an `-rc` tag is not a valid bundle version. This is harmless for an ad-hoc signed app.
